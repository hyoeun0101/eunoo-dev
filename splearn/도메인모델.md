# 1. Splearn 도메인
#### 스프런
- 스프런은 회원이 강의를 수강하는 온라인 서비스이다.
- 스프런은 스프링 프레임워크의 철학을 바탕으로 개발되고, 운영되며 발전하는 학습 생태계를 목표로 한다.
- 이 생태계를 구성하는 핵심 구성 요소는 학습(성장)하는 회원이다.
  - 그래서 이름이 Spring + Learner = Splearn
#### 회원
- 스프런에서 활동하기 위해서는 회원으로 등록해야 한다.
  - 단, 회원이 되기 전에도 스프런에 대한 소개와 강의 정보를 살펴볼 수 있다.
  - 강의를 수강하기 위해서는 등록을 완료하고, 활동 가능한 회원이 되어야 한다.
  - 등록 신청을 한 뒤 정해진 요건을 충족하면 등록이 완료된다.
  - 등록을 완료한 경우 프로필 주소, 자기 소개를 등록하거나 수정할 수 있다.
    - 프로필 주소는 알파벳과 숫자로 구성된 15자리 이내의 중복되지 않은 값
    - 탈퇴한 회원의 프로필 주소, 자기소개는 수정할 수 없다.
  - 등록 시간, 등록 완료 시간, 탈퇴 시간을 저장한다.

#### 강사
- 회원은 강사가 되어 다른 회원에게 강의를 제공할 수 있다.
  - 회원이 최초로 강사가 되기 위해선 강사 신청과 승인 과정을 거쳐야 한다.
  - 승인된 강사는 강의를 생성하고 검수를 거쳐 강의를 공개할 수 있다.
  - 공개된 강의는 회원에게 노출되고, 회원은 이 강의를 수강할 수 있다.

#### 수강
- 회원은 강의를 수강할 수 있다. 수강은 강의를 학습하는 것을 말한다.
  - 수강을 하기 위해선 먼저 수강 신청이 필요하다.
  - 무료 강의는 수강 신청과 동시에 수강이 가능하다.
  - 유료 강의는 수강 신청 후 강의비 결제를 완료해야 수강이 가능하다.
#### 수업, 섹션
- 강의는 영상, 문서와 같은 컨텐츠를 가진 하나 이상의 수업으로 구성된다.
  - 하나의 강의는 여러 개의 섹션과 섹션에 속한 수업으로 구성된다.
  - 수업과 섹션은 학습 순서를 가진다.
  - 학습 진도는 매 수업 단위로 기록된다.
  - 회원이 강의의 모든 수업을 학습하면 진도가 100%에 도달하고, 강의 수강 완료가 된다. 

# 2. 도메인 모델 (개념 식별하기)

## [회원 애그리거트]
### 회원(Member) - _Aggregate Root_
#### 속성
- `id`: `Long`
- `email`: `Email` - 이메일. 자연키(`@NaturalId`)
- `nickname`: 닉네임
- `passwordHash`: 암호화된 비밀번호
- `status`: `MemberStatus` - 회원 상태
- `detail`: `MemberDetail` - 회원 상세 (1:1)

#### 행위
- `static register(MemberRegisterInfo, PasswordEncoder)`: 회원을 등록한다. 상태는 `PENDING`, `MemberDetail`도 함께 생성한다.
- `activate()`: 가입을 완료한다. `PENDING`에서만 가능.
- `deactivate()`: 탈퇴한다. `ACTIVE`에서만 가능.
- `updateInfo(MemberUpdateInfoRequest)`: 닉네임, 프로필 주소, 자기 소개를 수정한다. `ACTIVE`에서만 가능.
- `changePassword(String, PasswordEncoder)`: 비밀번호를 변경한다.
- `verifyPassword(String, PasswordEncoder)`: 비밀번호가 일치하는지 확인한다.
- `isActive()`: 활동 가능한 회원인지 확인한다.
- `ensureActive()`: 활동 가능한 회원임을 보장. 아니면 예외.

#### 규칙
- 등록 직후 상태는 `PENDING`이다.
- 상태 전이는 `PENDING -> ACTIVE -> DEACTIVATED` 한 방향뿐이다.
- 비밀번호는 해시로만 저장한다.
- 이메일과 프로필 주소는 중복될 수 없다. (애플리케이션 계층 검사 + DB 유니크 제약)

### 회원상태(MemberStatus) - _Enum_
#### 상수
- `PENDING`: 가입 대기
- `ACTIVE`: 가입 완료
- `DEACTIVATED`: 탈퇴

### 비밀번호 인코더(PasswordEncoder) - _Domain Service_
#### 행위
- `encode()`: 비밀번호 암호화하기
- `matches()`: 비밀번호가 일치하는지 확인

### 이메일(Email) - _Value Object_
- 패키지: `domain.shared`
#### 속성
- `address`: 이메일 주소
#### 규칙
- 생성 시 이메일 형식을 검증한다. 

### 회원상세(MemberDetail)
#### 속성
- `id`: `Long`
- `profile`: `Profile` - 프로필 주소. 없으면 `null`
- `introduction`: 자기 소개
- `registeredAt`: 등록일시
- `activatedAt`: 등록완료 일시
- `deactivatedAt`: 탈퇴일시

#### 행위
- `static create()`: 회원 등록 시 현재 시간을 등록일시로 저장.
- `activate()`: 등록완료일시 저장.
- `deactivate()`: 탈퇴일시 저장.
- `updateInfo()`: 프로필 주소, 자기 소개 수정.

#### 규칙
- 등록완료일시, 탈퇴일시는 한 번만 설정할 수 있다.
- 프로필 주소가 비어 있으면 빈 문자열이 아니라 `null`로 저장한다. 유니크 제약에서 빈 문자열은 값으로 취급되기 때문.

### 프로필 주소(Profile) - _Value Object_
#### 속성
- `address`: 프로필 주소
#### 행위
- `url()`: 프로필 URL을 반환한다. (`@` + 주소)
#### 규칙
- 소문자 알파벳과 숫자로만 구성하고, 최대 15자.
- 어긋나면 `IllegalArgumentException`.

### 요청 객체 - _Record_
- `MemberRegisterInfo`: 등록에 필요한 값(`email`, `nickname` 5~20자, `password` 8~100자).
- `MemberUpdateInfoRequest`: 수정할 값(`nickname` 5~20자, `profileAddress` 최대 15자, `introduction` 최대 100자).

### 예외
- `DuplicationEmailException`: 이미 사용 중인 이메일.
- `DuplicationProfileException`: 이미 사용 중인 프로필 주소.

## [강사 애그리거트]

### 강사(Instructor) - _Aggregate Root_
#### 속성
- `id`: `Long`
- `member`: `Member` - 회원 (1:1)
- `status`: `InstructorStatus` - 강사 상태

#### 행위
- `static apply(Member)`: 강사 신청. 상태는 `PENDING`.
- `approve()`: 신청 승인. `PENDING`에서만 가능.
- `reject()`: 신청 거절. `PENDING`에서만 가능.
- `isActive()`: 승인된 강사인지 확인.
- `ensureActive()`: 승인된 강사임을 보장. 아니면 예외.

#### 규칙
- 가입 완료(`ACTIVE`)한 회원만 신청할 수 있다.
- 상태 전이는 `PENDING -> ACTIVE` 또는 `PENDING -> REJECTED`뿐이다.
- 한 회원은 한 번만 신청할 수 있다. (애플리케이션 계층 검사 + DB 유니크 제약 `member_id`)
  - 중복이면 `DuplicateInstructorApplicationException`.

### 강사상태(InstructorStatus) - _Enum_
#### 상수
- `PENDING`: 승인 대기
- `ACTIVE`: 승인 완료
- `REJECTED`: 거절

## [강의 애그리거트]
### 강의(Course) - _Aggregate Root_
- `Course`가 애그리거트 루트다. `CourseDetail`은 애그리거트 안에 있고, 항상 `Course`를 통해서만 변경한다. (`MemberDetail`과 동일한 패턴)

#### 속성
- `id`: `Long`
- `instructor`: `Instructor` - 강사 (N:1)
- `title`: 강의 제목
- `status`: `CourseStatus` - 강의 상태
- `detail`: `CourseDetail` - 강의 상세 (1:1)

#### 행위
- `Course(Instructor, String title, String description)`: 강의 생성. 강사는 승인 완료(`ACTIVE`) 상태여야 한다. 상태는 `DRAFT`, `CourseDetail`도 함께 생성한다.
- `submitForReview()`: 검수 신청. `DRAFT`에서만 가능.
- `publish()`: 강의 공개. `IN_REVIEW`에서만 가능.
- `archive()`: 강의 보관. `PUBLISHED`에서만 가능.
- `updateInfo(CourseUpdateInfo)`: 제목, 강의 소개 수정.
- `isPublished()`: 공개 상태인지 확인.
- `ensurePublished()`: 공개 상태임을 보장. 아니면 예외.

#### 규칙
- 상태 전이는 `DRAFT -> IN_REVIEW -> PUBLISHED -> ARCHIVED` 한 방향뿐이다.
- 검수 신청(`submitForReview`)은 강의 소개(`detail.description`)가 등록되어 있어야 가능하다.
- 강의 생성은 승인된(활성) 강사만 할 수 있다.
- 동일 강사가 동일한 제목의 강의를 만들 수 없다. (애플리케이션 계층 검사 + DB 복합 유니크 제약 `instructor_id + title`)
  - `Member`의 이메일/프로필 주소 중복 검사와 달리 전용 예외를 두지 않고, 위반 사항을 모아서 `ValidationException`(에러 메시지 목록)으로 던진다.

### 강의상태(CourseStatus) - _Enum_
#### 상수
- `DRAFT`: 초안
- `IN_REVIEW`: 검수 신청
- `PUBLISHED`: 공개
- `ARCHIVED`: 보관

### 강의상세(CourseDetail)
#### 속성
- `id`: `Long`
- `description`: 강의 소개. 없으면 `null`
- `createdAt`: 생성일시
- `publishedAt`: 공개일시
- `archivedAt`: 보관일시

#### 행위
- 생성자(package-private): 강의 생성 시 현재 시간을 `createdAt`으로 저장.
- `publish()`: 공개일시 저장.
- `archive()`: 보관일시 저장.
- `updateInfo(CourseUpdateInfo)`: 강의 소개 수정.

#### 규칙
- `Course`를 통해서만 생성/변경되며, 직접 생성자를 호출할 수 없다(패키지 프라이빗).

### 요청 객체 - _Record_
- `CourseCreateRequest`: 강의 생성에 필요한 값(`instructorId`, `title` 2~100자, `description` 최대 500자).
- `CourseUpdateRequest` / `CourseUpdateInfo`: 수정할 값(`title` 2~100자, `description`). `CourseUpdateRequest.toInfo()`로 도메인 요청 객체로 변환한다.

### 수강(Enrollment) - _Aggregate Root_
#### 속성
- `id`: `Long`
- `member`: `Member` - 수강 회원 (N:1). 자연키(`@NaturalId`)
- `course`: `Course` - 수강 강의 (N:1). 자연키(`@NaturalId`)
- `status`: `EnrollmentStatus` - 수강 상태
- `enrolledAt`: 수강 신청일시
- `completedAt`: 수강 완료일시

#### 행위
- `static enroll(Member, Course)`: 수강 신청. 상태는 `ENROLLED`, 신청일시 저장.
- `startStudying()`: 학습 시작. `ENROLLED`에서만 가능.
- `complete()`: 수강 완료. `STUDYING`에서만 가능. 완료일시 저장.

#### 규칙
- 가입 완료(`ACTIVE`)한 회원이 공개(`PUBLISHED`)된 강의만 신청할 수 있다.
- 상태 전이는 `ENROLLED -> STUDYING -> COMPLETED` 한 방향뿐이다.
- 한 회원은 같은 강의를 한 번만 신청할 수 있다. (애플리케이션 계층 검사 + DB 복합 유니크 제약 `member_id + course_id`)
  - 중복이면 `IllegalArgumentException`.

### 수강상태(EnrollmentStatus) - _Enum_
#### 상수
- `ENROLLED`: 수강 신청
- `STUDYING`: 학습 중
- `COMPLETED`: 수강 완료

### 요청 객체 - _Record_
- `EnrollRequest`: 수강 신청에 필요한 값(`memberId`, `courseId`). 둘 다 필수.


## [커리큘럼 애그리거트]
### 커리큘럼(Curriculum) - _Aggregate root_
#### 속성
- `id`: `Long`
- `course`: `Course` 강의. 1대1
- `sections`: `List<Secetion>` 섹션 목록-순서있음
#### 행위
- `Curriculum(course)`: 생성
- `addSection(title)`: 섹션을 맨 끝에 추가
- `addSection(sectionIndex, title)`: 지정 위치에 섹션 삽입
- `addLesson(sectionIndex, title)`: 지정 섹션에 수업 추가
- `updateSectionTitle(sectionIndex, title)`: 섹션 제목 수정
- `updateLessonTitle(sectionIndex, lessonIndex, title)` : 수업 제목 수정
- `removeSection(sectionIndex)`: 섹션 삭제
- `removeLesson(sectionIndex, lessonIndex)`: 수업 삭제
- `moveLesson(fromSection, fromLesson, toSection, toLesson)`: 수업 이동
- `validate()` : 등록된 섹션과 수업이 구성 조건을 만족하는지 확인
- `firstLesson()`: 첫 수업 반환
- `nextLesson(lesson)`/`nextLesson(lessonId)` : 다음 수업 반환
#### 규칙
- 마지막 남은 섹션을 삭제할 수 없다.
- 섹션 삭제 시 수업은 이전 섹션의 끝으로 이동한다. 단 첫 섹션일 경우, 다음 섹션의 맨 앞에으로 이동.
- 수업의 전체 순서는 섹션 순서 + 섹션 내 수업 순수로 결정된다.
- 빈 섹션은 첫/다음 수업 탐색 시 건너뛴다.
- 최소 1개의 섹션과 최소 1개의 수업이 있어야 한다. 수업이 없는 빈 섹션은 존재하면 안된다.
